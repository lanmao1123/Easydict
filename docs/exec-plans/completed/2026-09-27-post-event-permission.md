# 避免设备控制权限重复弹窗

状态：completed

## 任务契约

- 目标：修复 macOS 27 上 Yaomao 偶发的“设备控制和数据访问”弹窗。
- 授权：用户明确要求修复；只修改权限检查、模拟事件调用点、必要的本地化与本计划。
- 现场：初始 HEAD 为 `36991c022c92fc66808a9a60cc8d3ab9400ef948`；暂存区和已跟踪工作树为空；`build2/` 为已有未跟踪目录，保持不动。
- 验收：未获发送事件权限时，不因后台菜单检测直接投递模拟事件；自动粘贴只在用户首次实际使用时请求一次，后续可通过系统设置授权；静态检查通过。

## 实施

1. 为自动粘贴增加发送事件权限预检、一次性请求记录和清晰的本地化提示。
2. 为菜单快捷键的模拟事件增加无弹窗的权限预检。
3. 去掉只读辅助功能状态查询的弹窗副作用。
4. 运行差异检查、Swift 格式检查和项目要求的语法验证，记录结果。

## 结果与验证

- 自动粘贴先分别预检辅助功能和事件发送权限；每种系统授权只主动请求一次，拒绝后显示本地化提示。
- 菜单快捷键只有在已获事件发送权限时才模拟输入；只读辅助功能查询不再触发授权提示。
- `xcrun swiftc -frontend -parse`、`jq -e .`、`git diff --check`、SwiftFormat lint 和 Debug `xcodebuild build` 通过。构建内置 SwiftLint 检出 14 个原有非严重违规，未修改无关代码。
- 未在用户正在运行的 `/Applications/Yaomao.app` 上触发权限请求；真实系统授权流程需由用户在更新应用后验证。

## 风险

- macOS 授权由系统管理；代码无法静默补授。用户拒绝后，相关模拟输入功能需要在系统设置中重新开启。
- 未授权时菜单关闭辅助动作会跳过，避免后台触发系统弹窗。
