# 停止设备控制权限重复弹窗

状态：completed（2026-09-27）

## 任务契约

- 目标：修复已安装新版 Yaomao 后仍反复出现的 macOS“设备控制和数据访问”弹窗。
- 授权：用户明确要求彻底修复；允许修改事件监听调用点、必要的验证记录和本计划。
- 现场：初始 HEAD 为 `40be65897cc8a01617d39ed53220412183d1008e`；暂存和已跟踪工作树为空；`build2/` 是已有未跟踪目录，保持其路径不纳入提交。
- 证据：macOS TCC 日志显示 `kTCCServiceListenEvent` 的既有代码要求与当前应用不匹配；Yaomao 日志显示贴图手势 tap 每 30 秒失效并重建。截图产生于该循环期间。
- 验收：没有事件监听授权时，不创建全局 CGEvent tap；已有 tap 失效后不会无限重建；贴图基本缩放仍可通过本地手势处理；构建、语法和格式检查通过，并在新安装包中进行运行验证。

## 实施步骤

1. 在贴图手势 tap 创建前预检监听授权，缺失时使用无需 tap 的回退路径。
2. 对失效 tap 停止周期性重建；检查其他 CGEvent tap 创建点，避免相同弹窗路径。
3. 构建、安装并使用 Debug URL 驱动贴图行为，观察超过一个健康检查周期的日志。
4. 记录验证结果、归档计划和历史，然后按仓库规则处理本地提交。

## 风险

- 系统权限仍由 macOS 管理；旧 TCC 授权记录不会被应用静默修复。
- 没有事件监听授权时，贴图跨应用的全局手势可能受限，但本地贴图缩放应继续可用。

## 实际结果与验证

- 贴图、快捷键事件 tap、按键展示和滚动截图的 tap 均在创建前预检事件监听授权；贴图 tap 失效后停用定时检查并切换手势监控。
- Debug 构建成功；四个改动的 Swift 文件通过 `swiftc -frontend -parse` 与 SwiftFormat lint，`git diff --check` 通过。
- 将签名后的 Debug 包安装到本机应用程序目录并通过签名校验。无事件监听授权时，贴图日志只出现本地手势回退，没有创建 tap；跨过原 30 秒检查周期后无重建记录；调试缩放改变了贴图尺寸，本地手势事件被处理。
- 图形界面自动化接口超时，因此没有通过该接口验证系统弹窗是否消失；后续仍需观察用户实际使用是否复现。
